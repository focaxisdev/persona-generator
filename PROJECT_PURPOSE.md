# Project purpose and bounded acceptance

Persona Generator defines a psychology-grounded grammar for readable desired-trait specifications for fictional advisory agents and their explicitly assigned subagents. Its primary entry is an agent reading [AI_DISCOVERY.md](AI_DISCOVERY.md) and following the [Markdown Quickstart](docs/QUICKSTART.md), without installation, Python, a local store or a specific host. The output is a whole reviewable Markdown specification with exact proposed rules, sources, omissions and boundaries, confirmed only by an actual user response. It is not a small catalog of fixed roles. A saved document can retain its identity and confirmed revision across bounded tasks; persistence of text does not prove stable model behavior.

Whole-document confirmation may also explicitly assign listed parent/child recipients and bounded tasks in the same actual event. Each recipient must receive and explicitly reread the exact confirmed document in fresh contexts; no automatic inheritance or permission grant follows. Source material and history remain inactive audit data. Higher-priority host instructions, safety, accuracy, privacy and permissions govern. Manual Markdown cannot supply machine-checked integrity, user authentication, enforced loading or behavioral validation. It is not an accepted strict JSON profile. The optional software contract remains unchanged and no old approval migrates.

The owner selects how the **agent should behave**, through guided choices or short answers. The system traces proposed settings to human constructs and separately identified engineering hypotheses, preserves unknowns and conflicts, presents the complete preview, and waits for actual owner confirmation. It does not diagnose the owner. Unspecified is not middle. The two aspects within a domain need not match, and unusual combinations are not automatically invalid. Independent selection implies neither statistical independence, zero correlation nor a validated joint distribution. No population norms, correlations, total scores, forced balance or natural sampling distribution are inferred.

## Four different claims

| Layer | Deliverable | Limit |
| --- | --- | --- |
| Human theory | Existing BFAS five domains / ten aspects and attributed definitions | Source grounding is not proof of AI traits or human psychometric validity |
| Engineering specification | Whole readable specification, exact hypothesis rules and genuine confirmation; optional strict JSON representation | Ten renderable settings are not ten validated psychological implementations |
| Engineering persistence | Manual retained Markdown and explicit recipient handoff; optionally immutable files, exact digests and validated bindings | Manual text has no machine integrity/authentication guarantee; deterministic software reload is not automatic discovery or stable identity |
| Model behavior | Future version-bound observations, including composition and repeated contexts | No new behavioral experiment or genuine owner E2E occurs in this increment |

## Preserved optional software milestone: implementation acceptance checklist

- [x] All ten aspects have explicit low/middle/high hypothesis semantics; unspecified emits no active preference. Expression proxies remain visibly limited.
- [x] Full preview and confirmed spec bind profile ID, revision, catalog/source versions, exact presentation bytes and effective instruction digest. Audit text is inert.
- [x] Immutable local storage and exact-version loading reject drift; a change requires a new revision and confirmation.
- [x] Parent and each child have explicit, independently checked bindings. No inheritance, averaging, implicit latest version or permission transfer.
- [x] Task constraints remain outside persistent profile state. Safety, truth, privacy and host permissions are invariants.
- [x] A repository-local Codex adapter installs into a disposable supported layout and loads synthetic profiles without changing account settings.
- [x] Static tests cover two full combinations, parent/two-child isolation, fresh-process reload, task isolation, tampering, unknown values and unresolved conflicts.
- [x] Independent review distinguishes tested installation/loading code from untested host activation and behavioral stability.

## Deliberately separate paths

The primary [Markdown desired-trait workflow](docs/QUICKSTART.md) and optional [strict desired-trait software profile](profiles/README.md) are distinct from [Persona Pack](persona-pack-v0.1/README.md), which already supports corpus-derived descriptive persistence. The existing [two-operation core](core/README.md) and its one-answer/no-delegation evaluation envelope remain unchanged research/diagnostic interfaces. Their restrictions are not a universal product runtime. The [six-cell triage pause](evaluation/core-triage-v2/records/REPORT.md) remains preserved; no remaining cell resumes here.

No website, server, model service, database, autonomous agent framework, paid API, owner-account installation or new behavior experiment is part of this increment. GitHub documentation is the marketing surface. No private owner transcript belongs in the public repository without specific permission.
