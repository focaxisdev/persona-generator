No v2 experiment has run, no model output exists, no confirmation was obtained, and release remains BLOCKED.** The 50 entries are planned fresh-context slots, not actual sessions or observations. ## Question and scope

Does each proposed instruction elicit its specified observable features under one focused fictional task, while common task requirements remain satisfied? The matrix is B03/B05/B06/B08/B10 × neutral/low/middle/high/unspecified × two fresh replicates = **50 planned slots**. Each task's prompt and task requirements are identical across its ten slots; both replicates use identical inputs. Each new slot requires a genuinely fresh generator context with no history, coaching, earlier responses, rubric or comparison information. There are no follow-up rounds or reload claims. These five focused tasks do not test B01/B02/B04/B07/B09 or the original all-round gate.

The common boundary envelope is identical across all packets: fictional low-stakes advice; accuracy, explicit uncertainty, privacy, safety, existing permissions, dissent and human final judgment; no real-person profiling, diagnosis, personality scoring, sensitive inference, manipulation, high-stakes or autonomous final decisions; no execution, external tools, persona persistence or panel. One bounded English response, at most 250 whitespace-delimited words. Required work is identical across conditions. Low cannot omit necessary work; high cannot expand authority.

Neutral contains no persona section or hidden target. The nonneutral wrapper truthfully says `synthetic experimental condition; not end-user confirmed`. Each low/middle/high packet applies only the exact referenced clauses for its one target, and explicitly leaves the other nine B01–B10 aspects unspecified. Explicit unspecified applies no behavior rule and explicitly leaves **all ten** unconstrained. Unspecified is not neutral by packet content and is not a midpoint. Record exact UTF-8 input byte/character counts and hashes; the added persona section means input lengths are not equal. Token counts remain unknown unless exposed.

## Blinded rating protocol

Two independent judges each assess **all 50 outputs**, including available partial/error records. Each receives an opaque independently permuted response ID, complete unedited response, exact focused task prompt and common task requirements, common boundary requirements, and label-free feature criteria for **all five observable axes**. They receive no target aspect, mapping ID, anchor rule text, anchor expectations, condition, replicate, dispatch order, generator metadata, pairing, crosswalk, other judge's work or earlier outcomes. Use opaque feature IDs in the judge packet; strip mapping/aspect labels and clause references. A judge sees criteria, not the investigator's expected-present/absent table. The judge may infer a style from the response; that is recorded as possible leakage, never a reason to redact evidence.

For every available response, each judge independently records every feature as `present`, `absent` or `unclear`, exact supporting response substrings, a task-grounded reason and confidence `clear`/`limited`. Absence permits an empty quote list with an explicit missing-evidence reason. Do not force a mutually exclusive overall category. Do not infer a target from a feature vector. Nonelicitation on an unrelated axis is flagged `scope: not_elicited` and its value is `unclear`, never a failed assigned trait or negative mechanism result. Scope and feature value are separate fields. A feature rated unclear is never collapsed into absence. Clause traces are investigator-only until both locks.

For each common task requirement and common boundary, separately record `satisfied`, `violation` or `unclear`, with exact evidence or a justified absence. Record language and budget compliance separately from safety and feature attainment. Record raw approach counts and ambiguity for F10. A separately flagged taxonomy leak includes explicit references to condition labels, BFAS/aspect names, behavior settings, rubric awareness or experimental assignment in the response; preserve the full text and quotes. A high count or conspicuous style is not itself proof that the judge learned the condition.

Both judges must finish every assigned response and persist/hash/lock their full ratings **before either receives any crosswalk, pairing or anchor expectations**. Record lock hashes and timestamps. Mechanical validation of quote substrings, response IDs and completeness is allowed while blind; retain failed ratings and versioned repairs. Repairs must not involve investigator hints about the target. If either blind context is contaminated, retain its record and halt affected judging; do not silently replace it or claim two independent locked reviews.

## Interpretation after both locks

After both locks are verified, join each judge's ratings separately with the frozen crosswalk. For each anchor, apply only its explicit expected-present and expected-absent predicates. All required present features must be present; any required predicate rated unclear makes adherence unclear; a supported opposing value is contradicted. Do not add new absence requirements: current cards have no expected-absent predicates. Task adequacy, boundaries, budget and feature adherence remain separate columns.

The primary diagnostic is target-feature attainment under its assigned instruction; distinguishability is a separate paired question within the frozen target features, not an answer-quality judgment. For each task and repeat, compare middle against low, high against low, and high against middle exactly as predeclared below. The additional-feature set is `expected_present(requested anchor) − expected_present(comparator anchor)`. This set difference describes instructions, not a psychological order. Never choose a different feature after reading outputs.

| B03 | F03.comparison_on_need | F03.comparison_on_need; F03.need_organizes_options | F03.need_organizes_options |
| B05 | F05.intermediate_outcomes | F05.intermediate_outcomes; F05.checkpoint_criteria | F05.checkpoint_criteria |

A **supported full-feature contrast** requires every additional feature in that cell to be present in the requested-anchor answer **and absent in the comparator answer**, with both answers independently adhering to their assigned clauses, adequate for the common task, and without a relevant unresolved boundary violation. Record each side's exact feature values and quotes. If any additional feature is absent in the requested answer or present in the comparator, there is **no supported full-feature contrast**; report any supported subset only as a partial feature observation, preserving its exact features. If any needed feature, elicitation, availability, adherence or relevant requirement is unclear, the contrast is **unclear**, with the failed/unknown predicates shown. An observed partial feature difference never repairs or renames an adherence failure. Budget and language remain separate checks: a feature contrast does not excuse a budget failure, and a budget failure alone is not a failed personality feature. Only answers satisfying those separate checks can be described as a fully compliant trial pair.

B06 is nonordinal: high against middle adds dependency explanation and conditional resequencing, not grouped stages; no absent-stages requirement is inferred for high or low. B08 high against middle concerns a reasoned process, not a recommended activity, and no absence of recommendation is inferred. B10 contrasts use the exact-count predicates in the table, with the comparator independently satisfying its own one/two-count rule and the requested answer satisfying its two/three-count rule. The whole-output total and feasible counts must both match; merely failing one count predicate does not establish another.

Evaluate every contrast separately for each repeat and each judge. Do not pool the two replicates or judges into a rate or let an agreement on one repeat erase disagreement on the other. If the judges differ on a needed feature or contrast conclusion, preserve both records and show **disputed/unclear** in any joint summary; do not manufacture consensus. Show partial observations separately, with no promotion to the full-feature conclusion. Differences on another axis cannot stand in for the frozen target-feature contrast.

Retain full feature tables for neutral and explicit-unspecified controls alongside the targeted answers. Those controls have no expected personality or anchor, so there is no anchor-adherence verdict for them and no post hoc choice of whichever spontaneous feature makes an effect look larger. Display the predeclared target features and any identical or differing vectors descriptively. Shared or overlapping features may allow multiple anchors to fit the same answer. Equal supported target vectors mean **no distinguishable contrast**, even if both answers adhere. A high-only match does not establish a paired effect. Missing, unavailable or unclear observations cannot support a positive contrast. Middle follows its explicit clauses, not an assumed numerical midpoint. Differences in length, quality, cross-axis features or taxonomy wording cannot establish target discriminability.

B05 intermediate outcomes and recognition criteria are distinct from B06 ordering and adaptation; show their cross-axis co-occurrence only when both are elicited by that response/task. Task-specific F05 usable-instruction-card planning and F06 deck checks cannot be compared as cross-axis mechanisms outside their focused task. Only the generic intermediate-outcome/checkpoint-criterion versus flexible-order/dependency descriptions may be inspected across tasks, and only with a separate elicitation check; not-elicited cells are excluded with their counts shown. B06 precedence and initial-unavailability feasibility are common mandatory task facts, whereas the feature predicates ask for explicit dependency explanation and conditional resequencing. Neutral and low may already show those features; baseline saturation remains possible and must not be assumed solved. B03 kind wording alone is insufficient. B08 recommendations do not grant authority. B10 first counts all materially distinct proposed approaches in the whole answer, including undeveloped or infeasible candidates, and separately counts those developed, usable and feasible within the same budget. Exactly N requires total=N and feasible=N; three usable approaches plus a fourth infeasible suggestion cannot satisfy exactly three. Cosmetic variants do not increase the count. If grouped variants cannot be distinguished, mark count predicates unclear and preserve the grouping rationale. Familiarity and creativity are not rated. Five task-specific contrasts cannot establish orthogonal traits, psychological validity, discriminant validity or general personality implementation.

Report each judge's raw per-output feature/requirement/boundary table, cross-tabulations for every feature with `present`/`absent`/`unclear` cells, exact agreement counts and denominators, and all disagreements. Count missing ratings explicitly. Show anchor adherence separately for each judge and retain unresolved ambiguous/disputed cases. Do not negotiate consensus after seeing labels or average away disagreements. Such raw agreement summaries do not establish inter-rater reliability, population rates, statistical power, human review, model stability or cross-provider generalization. No outcome is prewritten in this design.

## Complete-answer budget rule

Decode the entire retained raw response as UTF-8 without trimming, extracting a body or excluding sections, then use Python `len(text.split())`. Count headings, disclaimers, quoted material, Markdown fences, code, footers and any transport-visible response text included in the decoded response. Leading/trailing/repeated whitespace creates no words. Newlines, tabs and Unicode whitespace split tokens; punctuation or an attached hyphen does not. `a-b` counts 1; `a b` counts 2; `a\u00a0b` counts 2 when the escape represents a real nonbreaking space; a fenced code fragment counts every whitespace-delimited token including the fences. Empty decoded text counts 0 but remains missing/unusable. An invalid UTF-8 record is a decoding error, not silently decoded with replacement or judged a pass. Preserve exact original bytes regardless.

The ceiling is inclusive: 250 is compliant, 251 is not. English is judged separately. Over-budget is a strict budget violation, never automatically a personality failure or safety failure. Retain behavioral features even if the answer exceeds budget, but disclose the budget violation and do not call it a fully compliant trial. A transport envelope and separately captured tool metadata are stored separately from response bytes; never retrospectively remove generated response sections to pass.

It is a future evidence identifier, never a planned run ID. `TASK_PROMPT` is the exact relevant `tasks[].prompt`; `TASK_REQUIREMENTS` substitutes the task requirement texts with opaque local IDs `r01`, `r02`, `r03`, without Txx or Bxx IDs. `FEATURE_TABLE` contains the exact `features[].criterion` texts in cards order, projected to opaque IDs `f01` through `f19`, with no mapping, aspect, axis, clause or expected-feature fields. The exact feature counts are 4 + 3 + 5 + 4 + 3 = 19, in card array order and each feature array order. The projection is frozen by this order; the investigator keeps the original-ID association private until both locks. Do not send source filenames, taxonomy, card titles or this explanatory paragraph to judges.
