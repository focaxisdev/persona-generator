# v0.2.0-alpha UNCONFIGURED experimental source package — NOT RELEASED

**Prepared distribution scope: UNCONFIGURED source package.** An installable, psychology-source-grounded specification and composition layer for desired agent behavior. No owner profile, runtime store, binding or activation is distributed. Synthetic fixtures and old model outputs are inert examples/evidence, not defaults. AI mappings are experimental and scientifically unvalidated. These notes are not a tag, merge approval, release announcement or claim that the original scientific gate passed. See the separate prospective [package and scientific tracks](RELEASE_ACCEPTANCE.md).

## Current profile functionality

- Five Big Five domains / ten BFAS aspects have readable source definitions and separately versioned low/middle/high engineering rules. Unspecified stays inactive. Aspects are not facets, and settings are not psychological scores or norms.
- Choose guided questions **or** short answers about desired agent behavior. Skip unwanted settings; inspect unknowns, conflicts, exclusions and the complete exact preview. No human personality diagnosis, forced balance or mandatory edit.
- Preserve the approved spec, exact presented preview, catalog/source pins and immutable revision in a local store. Structural receipts cannot authenticate real consent.
- Explicitly assign a parent and any desired children to the same or different exact revisions. No child, inheritance, blend or population correlation is invented. Review every assignment with the owner before binding.
- Revalidate and render only trusted active rules through the portable local loader. Repository-guided host use reads the installed skill and invokes the loader; it does not require another Codex CLI or automatic discovery.
- Deliberate replacement requires the current validated binding digest. Rollback rebinds a retained valid revision using the **current** binding digest; it does not rewrite historical files or publish a lower revision. The guard is neither owner authentication nor a concurrent transaction.

## Runtime requirements

Python **3.9 or newer** and the standard library are required; runtime dictionary union sets the implementation minimum. Actual execution was tested on **Python 3.12.14 only**. No execution-tested compatibility with Python 3.9, other versions or other hosts is claimed. Entry-point version guards reject a reported version below the minimum before normal work. See [source packaging](SOURCE_PACKAGE.md) and [verification](PACKAGE_VERIFICATION.md).

## Versions and compatibility

The proposed package name `v0.2.0-alpha`, `persona-profile-v1` schema, catalog IDs and individual `hyp.*` IDs describe different layers. Catalog v2 adds `hyp.politeness.v2`: high Politeness falls back to a neutral acknowledgment when neither supported merit nor an explicitly stated aim is available. Catalog v1, its fixtures and existing exact confirmed specs remain supported unchanged. Changing a profile or catalog requires a new preview/revision/confirmation; rollback to unchanged retained content requires approval of the assignment, not fabricated new content approval. No automatic migration or evidence transfer occurs.

The historical two-operation `persona-core-v1` supports only planning structure and advisory initiative in its own diagnostic contract. That limitation does **not** describe the current ten-aspect profile layer. Core's ephemeral, one-answer/no-delegation envelope remains unchanged and is not the universal product runtime. Persona Pack retains its separate corpus-derived descriptive-persistence role; scenario rehearsal and panels remain optional legacy paths.
